# NIT's dialog frame: the decision and how to revisit it

**Decision (owner, 2026-09-28):** keep Vaultkeeper's dialogs as they are, with
this document good enough to choose option A or B later without redoing the
research. Nothing in the product changed for this decision.

## What NIT's frame is

Most NIT dialogs share one frame, read from NIT's own control dumps
(`nit/<Form>.controls.txt`) and Designer files:

```
┌────────────────────────────────────────────────────────────┐
│ [icon 32×32]  Description of what this dialog does,     (?)│  header (window colour)
│               one or two lines.                             │
├────────────────────────────────────────────────────────────┤
│                                                            │
│   the dialog's own content                                  │
│                                                            │
├────────────────────────────────────────────────────────────┤
│ Status text (MsgLabel)                    [Save] [Cancel]   │  footer band (WhiteSmoke)
└────────────────────────────────────────────────────────────┘
```

| Part | NIT control | Geometry (typical) | Notes |
|---|---|---|---|
| Header icon | `PictureBox Pic<Form>` | 32×32 at 3,3 | a per-dialog image (see the inventory) |
| Description | `Label Lb<Form>` | from x = 41, one or two lines | NIT's wording, per dialog |
| Help | `ButtonLabel Bh<Topic>` | 22×22, top right | a round blue "?"; its name is the help topic |
| Status | `MsgLabel MiStatus / MlStatus / MgInfo` | footer left | info / warning / error colouring |
| Buttons | `ButtonPlus` | 75×23, footer right | Save / Cancel, or the dialog's own |
| Footer band | `TableLayoutPanel LpActions` | full width | `BackColor = WhiteSmoke` |

The **per-form inventory** is in [`frame_inventory.md`](frame_inventory.md),
generated by `frame_inventory.py`. It gives each NIT form's header icon (and
whether Vaultkeeper already bundles it: 16 do, 2 would need copying), its
description, its help topic, its status label and its footer buttons.
Vaultkeeper's help topics already use NIT's names (`help_button("BhHelp")`), so
the "?" would open the same pages the Help buttons open now.

## Vaultkeeper today

- A plain description label at the top, where the dialog has one.
- A **Help** button at the bottom left, with the dialog's buttons at the bottom right.
- Status or summary lines as plain labels above the buttons.

## The options

Previews render three real dialogs in each option, in light and dark themes:
`frame/<Form>-light.png` and `frame/<Form>-dark.png` (Hak Patch Editor, Alias
Section Editor, Workshop Viewer). Regenerate them with:

```bash
VK_SCRIPT=frame_prototype.py docs/screen_parity/run_vk_shots.sh
```

| Option | What changes | Pros | Cons | Effort |
|---|---|---|---|---|
| **Keep** (chosen) | nothing | no churn; consistent with every VK dialog today | VK dialogs do not look like NIT's | — |
| **A: header only** | adds NIT's icon, description and "?" at the top; the footer stays | instantly recognisable to NIT users; buttons do not move | two ways to open help (the "?" and the Help button) unless Help is dropped | small: one helper, then about 25 dialogs |
| **B: full frame** | A, plus the footer band: status on the left, buttons on the right, Help moves into the "?" | closest to NIT | touches every dialog's bottom row and many tests that find buttons | medium: one helper, about 25 dialogs, and test updates |

## How to implement A or B later

1. **A helper, `ui/dialog_frame.py`:**
   - `DialogHeader(icon, text, help_topic)` is the strip that
     `frame_prototype.header()` builds.
   - `DialogFooter(status_label, buttons)` is the band from
     `frame_prototype.dress()`.

   Colours come from the palette, never hex. The band is a shade of `Window`,
   darker in light themes and lighter in dark ones. Keep Fusion; see `CLAUDE.md`.
2. **Per dialog:**
   - Take the icon and description from `frame_inventory.md`.
   - Keep the dialog's own information lines. The prototype hides the old
     description label, and on the Workshop Viewer that label also carried
     "not configured", which must stay visible.
   - In B, the dialog's existing status or summary label becomes the footer's
     status label.
3. **Help:** the "?" calls the same `HelpViewer.show_for_control(<topic>)`. In B
   drop the Help button; in A decide whether to keep it.
4. **Tests:** most dialog tests find buttons by attribute, not by position, so A
   touches few tests. B moves widgets between layouts, so check tests that walk
   the bottom layout.
5. **Order:**
   - Do the dialogs NIT users open most first: Installation Manager, Game Saves
     Manager, Settings, Download Project.
   - Then the editors: Hak Patch, Alias, Dependency, Wizard Builder.
   - Then the viewers.
6. **Verify:**
   - Re-render with `run_vk_shots.sh`.
   - Update `pairs/` and check both themes.
   - Re-run `actions_diff.py` to confirm nothing lost an action.
