# Control-set parity findings (2026-07-24)

The form + action guardrails prove every VB dialog has a dedicated port surface and
every command is wired. This is the **deeper layer**: does each bound dialog reproduce
the original's *individual controls*? Generated by `check_control_parity.py` (lead
generator) + a subagent evidence pass + orchestrator adjudication.

Status legend: **THIN-OUT** = real capability reduced, fix-by-default · **BOUNDED** =
documented/accepted reduction · **DEFERRED** = data-blocked/cross-platform/low-value.

For each open item: the VB source, the port file, what's missing, and whether it's
groundable — enough for another agent to pick up and fix.

## Method note

`check_control_parity.py` is a *lead generator*, not a verdict — WinForms↔Qt caption/widget
wording differs, so a flagged control may be present under another label (subagents confirmed
several StartScreen actions were merely renamed). Always adjudicate each flag against both
sources before acting. Cheap subagents reliably report present/absent (the factual layer);
the orchestrator decides THIN-OUT vs BOUNDED.
